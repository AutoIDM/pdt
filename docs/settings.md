# Settings

This page lists every setting that pdt accepts. It gives the place of each setting, its allowed values, its default, and what it does. For command options, see [Commands](commands.md).

## Where settings go

| Place | What it holds | Who writes it |
| --- | --- | --- |
| The project's `pdt.yml`, in the project folder | Settings for every app in the project. | `pdt init` and `pdt alerts setup` create parts of it. You edit it. A deploy saves values that it finds. |
| The app's `pdt.yml`, in the app folder | Settings for that one app. `config.yml` is its deprecated name; pdt reads it when the folder has no `pdt.yml`. | `pdt new` creates it. You edit it. `pdt pause`, `pdt unpause`, and a deploy save values in it. |
| `.env` file | Secrets and other env vars. Never commit this file. | `pdt init` creates it. You edit it. pdt saves sign-in values and alert URLs in it. |
| An env var in the terminal or the CI variables | One value for one process. | You, or your build server. |
| `.pdt/state` in the project folder | The record of each deployed app. | pdt. Do not edit this file. |

An env var is an environment variable, a named value that a program reads when it starts.

A project looks like this:

```
my-jobs/
  pdt.yml           settings for every app
  .env              secrets, never committed
  .pdt/state        the record of deployed apps
  my-report/
    pdt.yml         settings for this app
    run.py          the job
```

## Which value pdt uses

pdt merges the settings for an app in this order, from lowest to highest:

1. The `platform:` block in the project's `pdt.yml`.
2. The entry of the app in the `apps:` list of the project's `pdt.yml`.
3. The app's `pdt.yml`.
4. Env vars. These change `config:` keys only, through `PDT_<APP>_<KEY>`.

Each kind of setting merges in its own way:

| Setting | How pdt finds the value |
| --- | --- |
| Each `platform:` key | Key by key, in the order above. A provider env var applies only when the merged key is empty. |
| Each `config:` key | Key by key: the `apps:` entry, then the app's `pdt.yml`, then `PDT_<APP>_<KEY>`. |
| `env:` | The whole `env:` block of the app's `pdt.yml`. When that block is empty, the whole `env:` block of the `apps:` entry. The two blocks do not merge. |
| `alerts`, `docker-build` | The top level of the project's `pdt.yml`, then the `apps:` entry, then the app's `pdt.yml`. The highest one replaces the others. |
| `timezone` | The first value in this list: top level of the app's `pdt.yml`, the `apps:` entry, merged `platform.timezone`, `Etc/UTC`. |
| Every other app key | The first value in this list: the app's `pdt.yml`, the `apps:` entry, the default. |

`pdt destroy` does not use this order for the place. It uses the place that `.pdt/state` records. See [The `.pdt` folder](#the-pdt-folder).

## Keys at the top level of the project's `pdt.yml`

| Key | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `platform` | A block of [`platform:` keys](#platform-keys). | No block. | Sets where every app runs. An app can replace each key. |
| `apps` | A list of [app entries](#app-keys). Each entry needs `name`. | No list. | Holds settings for each app. pdt finds an app from its folder, so an app does not need an entry. |
| `docker-build` | `auto`, `local`, or `cloud`. | `auto` | Sets where a deploy builds the image. See [`docker-build`](#app-keys). |
| `alerts` | A list of [alert entries](#alerts-entries), or `false`. | No list. | Sets where pdt sends events. An app can replace the list. |
| `error-watch` | `true` or `false`. | `true` | After a command fails at a terminal, pdt prints one line with a link to the pdt community. `false` turns off that line. pdt sends nothing anywhere. |

This `pdt.yml` shows every key at the top level:

```yaml
# pdt.yml
platform:
  provider: aws
  region: us-east-1
  account: "123456789012"
  timezone: America/Chicago

docker-build: auto
error-watch: true

alerts:
  - type: slack
    webhook: B0123ABC
    name: "#it-alerts"
    events: [app:deploy-failed, job:run-failed]

apps:
  - name: my-report
    schedule: daily
    platform:
      region: us-west-2
```

## `platform:` keys

Put these keys under `platform:` in the project's `pdt.yml`, in an `apps:` entry, or in the app's `pdt.yml`. pdt ignores a key that belongs to another provider.

### Keys for every provider

| Key | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `provider` | `aws`, `azure`, `google-cloud`, or `windows`. | No default. `pdt init` writes it. `pdt validate` reports an app with no provider. | Selects where the app runs. |
| `region` | A region name of the cloud provider, for example `us-east-1`. | No default. The first deploy suggests a region, asks you to confirm it, and saves the answer. With `--yes`, the deploy takes the suggestion. | Selects where the job and its data live. The `windows` provider does not use it. |
| `timezone` | A time zone name, for example `America/Chicago`. | `Etc/UTC` | Sets the time zone of the schedule for every app that does not set its own. The `windows` provider ignores it and uses the local time of the PC. |

### AWS keys

| Key | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `account` | A 12-digit AWS account ID in quotes, for example `"123456789012"`. | The first deploy reads it from your credentials and saves it. | Each later deploy checks that your credentials match this account. |
| `profile` | The name of a profile in `~/.aws`. | The default sign-in of the AWS SDK: `AWS_PROFILE`, the `default` profile, or `AWS_ACCESS_KEY_ID`. When that sign-in has no credentials, pdt uses the only profile on the computer. With several profiles, pdt asks at a terminal and saves the answer. On a build server, it stops. | Selects the sign-in that pdt uses. |

```yaml
# pdt.yml
platform:
  provider: aws
  region: us-east-1
  account: "123456789012"
  profile: work
```

### Azure keys

| Key | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `subscription` | An Azure subscription ID. | The active subscription of the Azure CLI (`az account show`). A deploy at a terminal saves it; a deploy with no one to ask (CI) uses it and does not save it. pdt asks nothing. When you are not logged in, pdt asks at a terminal to open the browser login, and a deploy with no one to ask stops. | Selects the subscription. When the Azure CLI uses another subscription, the deploy switches the Azure CLI to this one. |
| `resource_group` | A resource group name. | `pdt` | Names the resource group that holds the project's resources. |
| `environment` | An environment you already own, written as `<resource-group>/<name>`. | The shared environment `pdt-<region>` in the resource group `pdt-shared`. | Selects the Container Apps environment. pdt never creates, changes, or deletes an environment that you name here. |

```yaml
# pdt.yml
platform:
  provider: azure
  region: eastus
  subscription: 00000000-0000-0000-0000-000000000000
  resource_group: pdt
  environment: my-group/my-environment
```

### Google Cloud keys

| Key | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `project` | A Google Cloud project ID. | The deploy lists your projects, asks you to choose one, and saves the answer. | Selects the project. |

```yaml
# pdt.yml
platform:
  provider: google-cloud
  region: us-central1
  project: my-starter-project
```

### Windows keys

The `windows` provider uses only `provider`.

```yaml
# pdt.yml
platform:
  provider: windows
```

### The retired `runtime` key

The `runtime` key is no longer a setting. `pdt validate` reports it and tells you to remove it.

## App keys

Put these keys at the top level of the app's `pdt.yml`, or in its entry in the `apps:` list of the project's `pdt.yml`.

| Key | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `name` | The name of the app folder. | In the app's `pdt.yml`, the folder name. An `apps:` entry must have it. | Connects an `apps:` entry to an app folder. In the app's `pdt.yml` it must match the folder name. |
| `app_profile` | `job` or `web`. | `job` | Selects the kind of app. A `job` runs on a schedule and exits. A `web` app is an HTTP server behind a sign-in. See [App profiles](profiles.md). |
| `schedule` | `hourly`, `daily`, `weekly`, `monthly`, `yearly`, or a 5-field cron expression in quotes. | No schedule. The first deploy asks for one and saves it. With `--yes`, the deploy uses `daily`. | Sets when the job runs. The `windows` provider accepts fewer forms. See [Windows Task Scheduler](platforms.md#windows-task-scheduler). A web app has no schedule, and `pdt validate` reports one. |
| `timezone` | A time zone name, for example `America/Chicago`. | `platform.timezone`, then `Etc/UTC`. | Sets the time zone of this app's schedule. The `windows` provider ignores it. |
| `platform` | A block of [`platform:` keys](#platform-keys). | The `platform:` block of `pdt.yml`. | Replaces each named key for this app. |
| `config` | A block of your own keys. See [`config:` keys](#config-keys). | Empty. | Holds the settings that your app reads. |
| `env` | A block with [`env:` keys](#env-keys). | Empty. | Names the env vars that the app needs. |
| `storage` | `true`, `false`, or a block of [`storage:` keys](#storage-keys). | `true` | Gives the app a storage folder. See [Keeping files between runs](storage.md). |
| `web` | A block of [`web:` keys](#web-keys). | Empty. | Sets the port, the health check, the sign-in, and the size of a web app. Only a web app takes it. |
| `enabled` | `true` or `false`. | `true` | With `false`, every command except `pdt list` acts as if the app is not there. `pdt destroy` still accepts the app while it is deployed. A deployed schedule keeps running. Run `pdt pause` or `pdt destroy` first. |
| `pause` | `true` or `false`. | `false` | With `true`, the deployed schedule starts no runs. You can still start a run with `pdt run APP --deployed`. A paused web app is stopped. `pdt pause` and `pdt unpause` write this key. |
| `docker-build` | `auto`, `local`, or `cloud`. | The top-level `pdt.yml` value, then `auto`. | Sets where a deploy builds the image. `auto` uses Docker on this computer when Docker answers, else the cloud. `local` uses only Docker. `cloud` uses only the cloud. `pdt validate` reports this key for the `windows` provider. |
| `alerts` | A list of [alert entries](#alerts-entries), or `false`. | The top-level `pdt.yml` list. | Replaces the whole project list for this app. |
| `run_scripts` | See [PowerShell keys](#powershell-keys). | Not set. | Selects the scripts of a PowerShell app. |
| `continue_on_error` | See [PowerShell keys](#powershell-keys). | `false` | Runs the remaining scripts of a PowerShell app after a failed script. |

This app `pdt.yml` shows the common keys:

```yaml
# my-report/pdt.yml
schedule: "0 6 * * 1-5"
timezone: America/Chicago
storage: true
enabled: true
pause: false

config:
  email_from: reports@example.com
  lookback_hours: 72

env:
  required: [PDT_SMTP_HOST, PDT_SMTP_USER]
  one_of:
    - [PDT_SMTP_PASSWORD]
    - [PDT_SMTP_OAUTH_CLIENT_ID]
  optional: [REPORT_GREETING]
```

A cron value that starts with `*` must be in quotes, for example `"*/15 * * * *"`. pdt also accepts `@daily` and the other shorthand names with `@`.

### `storage:` keys

`storage: true` is the same as `storage: {enabled: true}`, and `storage: false` is the same as `storage: {enabled: false}`.

| Key | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `enabled` | `true` or `false`. | `true` | Gives the app its own storage folder. |
| `read` | A list of names of other apps in the project. | Empty. | Lets this app read the storage folder of each named app. A deployed web app finds each folder as read-only files under `/pdt/storage/<app>/`. A job opens it with `pdt.utils.storage.store(app="<app>")`; for a job, this works with the `azure` provider only. Run `pdt deploy APP` after you change the list. `pdt validate` reports a name that is not an app of the project, the app's own name, and an app with `storage: false`. |

```yaml
# dashboard/pdt.yml
storage:
  enabled: false
  read: [github-data]
```

### `web:` keys

These keys apply only to an app with `app_profile: web`.

| Key | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `port` | A number from 1 to 65535. | `8080` | Sets the port that the app listens on. pdt gives the app this number in `PDT_PORT`. The app must listen on `0.0.0.0`. |
| `health_path` | A path that starts with `/`. | `/` | Sets the path that the startup check requests. The deployed app must answer it with a 2xx or 3xx status within 90 seconds of its start, or the deploy fails. |
| `auth` | A block of [`web.auth:` keys](#webauth-keys). | No default. `pdt validate` reports a web app with no `auth`. | Sets who may use the app. |
| `resources` | A block of [`web.resources:` keys](#webresources-keys). | The default of each key. | Sets the size and the scale of the deployed app. |

### `web.auth:` keys

Every web app has a sign-in. `web.auth` needs `provider`, and `allowed_domains`, `allowed_groups`, or both.

| Key | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `provider` | `google`. | No default. The block needs it. | Puts Identity-Aware Proxy (IAP) in front of the app. A visitor signs in with a Google account before any request reaches the app. |
| `allowed_domains` | A list of Google Workspace domains, for example `[example.com]`. | Empty. | Lets every account of each domain enter. |
| `allowed_groups` | A list of Google group addresses, for example `[sales@example.com]`. | Empty. | Lets every member of each group enter. |

IAP sends the email of the visitor to the app in the header `X-Goog-Authenticated-User-Email`, as `accounts.google.com:<email>`. The app does not need to read it. A Python app can call `pdt.utils.auth.current_user(headers)`, which returns the email, or `""` when no one signed in, as in `pdt run`.

### `web.resources:` keys

| Key | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `cpu` | `1`, `2`, `4`, `6`, or `8`. | `1` | Sets the vCPUs of each instance. |
| `memory` | A size in `MiB` or `GiB`, from `512MiB`. At most 4 GiB for each vCPU. | `512MiB` | Sets the memory of each instance. Files that the app writes to its local disk use this memory. |
| `timeout` | A number of seconds from 1 to 3600. | `300` | Sets the longest time that one request may take. |
| `min_instances` | A number from 0 to `max_instances`. | `0` | Sets the instances that keep running with no requests. Each one costs money all the time. With `0`, the first request after an idle time waits for an instance to start. |
| `max_instances` | A number from 1 to 1000. | `3` | Sets the most instances that run at the same time. |
| `concurrency` | A number from 1 to 1000. | `80` | Sets the most requests that one instance serves at the same time. |

```yaml
# dashboard/pdt.yml
app_profile: web
web:
  port: 8080
  health_path: /
  auth:
    provider: google
    allowed_domains: [example.com]
    allowed_groups: [sales@example.com]
  resources:
    cpu: 1
    memory: 1GiB
    max_instances: 5
storage:
  enabled: false
  read: [github-data]
```

### `config:` keys

The `config:` block is free-form. You choose the keys and the values. A Python app reads the block as `app["config"]`. A PowerShell app reads it from `$env:PDT_CONFIG_JSON`. See [Writing your own app](writing-apps.md).

pdt checks only two things in this block:

- The block cannot hold a name of an app key, such as `schedule`, except `name`.
- An app that sends email with `pdt.utils.send_email` needs `email_from` here when an email env var is set. See [Sending email](email.md).

### `env:` keys

| Key | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `required` | A list of env var names. | Empty. | When one of these is not set, `pdt validate` reports it, and `pdt run` and `pdt deploy` stop. |
| `one_of` | A list of lists of env var names. | Empty. | At least one inner list must have every name set. |
| `optional` | A list of env var names. | Empty. | pdt does not stop when one of these is not set. |

A deploy sends each listed name that has a value to the app's secrets in the cloud. pdt never prints the values.

pdt also reads the app's code and adds each env var name that it finds:

- In Python, `os.environ["NAME"]` adds a required name. `os.environ.get("NAME")` and `os.getenv("NAME")` add an optional name.
- In PowerShell, `$env:NAME` adds a required name, unless the scripts set it. To make it optional, list it under `optional`.

This scan skips each name that starts with `PDT_`. List each `PDT_` name that your app needs, or the deploy does not send it. An alert entry adds its own webhook name, so do not list that name.

A name that ends in `_PATH` names a file. A deploy reads the file and sends its contents as `<NAME>_B64`. pdt looks for a relative path next to each `.env` file, then in the app folder, then in the project folder. A value for `<NAME>_B64` also satisfies a `required` name `<NAME>_PATH`. A deploy sends only the env vars that the app lists (in its own `pdt.yml` or its `apps:` entry), that pdt finds in the code, or that the alert settings need. To set `<NAME>_B64` yourself, list it too, for example under `optional`.

### PowerShell keys

These keys apply only to a PowerShell app.

| Key | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `run_scripts` | A list of `.ps1` file names in the app folder. The list cannot be empty. | Not set. pdt runs `run.ps1` when it exists. Otherwise, pdt runs every `.ps1` that no other `.ps1` loads, in name order. | Selects the entry scripts and their order. `pdt validate` reports this key when `run.ps1` exists, or when the app has no `.ps1` files. |
| `continue_on_error` | `true` or `false`. | `false` | With `true`, every entry script runs after a failure. The run still exits with the exit code of the first failed script. |

```yaml
# my-powershell-job/pdt.yml
schedule: daily
run_scripts: [get-users.ps1, send-report.ps1]
continue_on_error: true
```

## `alerts:` entries

An alert entry sends events to one place. Put the list at the top level of `pdt.yml` for every app, or in an `apps:` entry or the app's `pdt.yml` for one app. `pdt alerts setup` writes the list in `pdt.yml`, and `pdt alerts test` sends a test message.

With no `alerts:` key, pdt prints every event on the console. `alerts: false` turns off every event.

### Keys for every alert type

| Key | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `type` | `console`, `slack`, or `teams`. | No default. Each entry needs it. | Selects where the events go. `console` prints a line in the output of pdt and of each run. |
| `events` | A list of [event names](#event-names). | Empty. An entry needs `events`, `exclude-events`, or both. | Selects the events that the entry receives. |
| `exclude-events` | A list of [event names](#event-names). | Empty. | Removes events from `events`. |

A `console` entry takes only these keys.

### Slack keys

A `slack` entry needs `webhook` or `channel`, and cannot have both.

| Key | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `webhook` | The webhook ID from the Slack webhook URL, for example `B0123ABC`. | No default. | Selects the env var `SLACK_WEBHOOK_<ID>`, which holds the URL. |
| `channel` | A Slack channel name, for example `it-alerts`. | No default. | The older form. Selects the env var that holds the URL. `it-alerts` selects `SLACK_WEBHOOK_IT_ALERTS`. |
| `name` | Any text, for example `"#it-alerts"`. | The channel, or the webhook ID. | Sets the label that pdt shows for this entry. |

### Teams keys

| Key | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `webhook` | The workflow ID from the Teams workflow URL. Each `teams` entry needs it. | No default. | Selects the env var `TEAMS_WEBHOOK_<ID>`, which holds the URL. |
| `name` | Any text, for example `IT alerts`. | The workflow ID. | Sets the label that pdt shows for this entry. |

The webhook URL is a secret, so it goes in `.env` and not in the YAML file. `pdt alerts setup` saves it there. A deploy sends it to the job with the app's other secrets.

```yaml
# pdt.yml
alerts:
  - type: slack
    webhook: B0123ABC
    name: "#it-alerts"
    events: [all]
    exclude-events: [job:run-started, job:run-completed]
  - type: teams
    webhook: 0123456789abcdef
    name: IT alerts
    events: ["app:*", job:run-failed]
  - type: console
    events: [unhandled]
```

```
# .env
SLACK_WEBHOOK_B0123ABC=https://hooks.slack.com/services/T0123ABC/B0123ABC/replace-this-secret
TEAMS_WEBHOOK_0123456789ABCDEF=https://example.api.powerplatform.com/workflows/0123456789abcdef/replace-this-secret
```

### Event names

| Event | When pdt sends it |
| --- | --- |
| `app:deploy-started` | A deploy starts. |
| `app:deploy-completed` | A deploy succeeds. |
| `app:deploy-failed` | A deploy fails. |
| `app:destroy-started` | A destroy starts. |
| `app:destroy-completed` | A destroy succeeds. |
| `app:destroy-failed` | A destroy fails. |
| `app:secrets-updated` | The secrets of a deployed app change. |
| `job:run-started` | A run starts. |
| `job:run-completed` | A run succeeds. |
| `job:run-failed` | A run fails. |
| `job:paused` | `pdt pause` stops the schedule. |
| `job:unpaused` | `pdt unpause` lets the schedule start runs again. |

These names have a special meaning in `events` and `exclude-events`:

| Name | What it matches |
| --- | --- |
| `all` | Every event. |
| A name with `*`, for example `job:*` in quotes | Every event that matches the pattern. |
| `unhandled` | Every event that no entry receives through another name. |

When no entry names `unhandled`, pdt adds a `console` entry for `unhandled` to the end of the list. To stop this, add `exclude-events: [unhandled]` to an entry.

## Env vars you can set

### Project and output

Set these in the terminal or in the CI variables. pdt reads some of them before it reads a `.env` file, so do not put them in `.env`.

| Env var | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `PDT_PROJECT` | The path of a folder that holds `pdt.yml`. | pdt looks in the current folder, then in each folder above it. | Names the project folder. |
| `PDT_<APP>_<KEY>` | Any text. In `<APP>`, write `-` as `_`. `<APP>` and `<KEY>` are in capitals. | Not set. | Replaces the key `<key>` in the `config:` block of the app. `PDT_MY_REPORT_LOOKBACK_HOURS` replaces `lookback_hours` for `my-report`. The value is always text. A deployed job does not get this value. |
| `PDT_ERROR_WATCH` | `0`, `false`, `off`, or `no` turn off the line. | Not set. | Turns off the same line as `error-watch: false`. |
| `CI` | Any text. | Not set. Build servers set it. | pdt treats the computer as a build server. pdt asks no sign-in questions, creates no `.env` file, and prints no `error-watch` line. See [Running pdt from CI](deploy.md#running-pdt-from-ci). |
| `NO_COLOR` | Any text. | Not set. | Turns off color in the output. |
| `XDG_DATA_HOME` | A folder path. | `~/.local/share` | Sets the data folder on macOS and Linux. pdt keeps its downloads in a `pdt` folder inside it. |
| `XDG_CONFIG_HOME` | A folder path. | `~/.config` | Sets where `pdt completion` writes the fish shell file. |
| `ZDOTDIR` | A folder path. | Your home folder. | Sets where `pdt completion` finds the zsh `.zshrc` file. |
| `TZ` | A time zone name. | The time zone setting of the computer. | Sets the time zone that pdt uses to suggest a region. |
| `LC_ALL`, `LC_MONETARY`, `LANG` | A locale name, for example `en_GB.UTF-8`. | The monetary locale of the computer, then US dollars. | Sets the currency of the cost estimate on Linux. pdt uses the first one that is set. On macOS the currency comes from the `AppleLocale` system setting. On Windows it comes from the regional setting. |

### Values that can go in `.env`

Put these in `.env`, in the terminal, or in the CI variables. See [Which value wins in `.env`](#env-files).

| Env var | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `PDT_ENV_JSON` | One JSON object of names and values, for example `{"PDT_SMTP_USER": "reports@example.com"}`. | Not set. | Holds many values in one variable, for a CI system that keeps one secret. An env var or a `.env` value with the same name wins. A deployed app also gets its secrets through this name. |
| `SLACK_WEBHOOK_<ID>` | A Slack webhook URL. | Not set. | Holds the URL for a [Slack alert entry](#slack-keys). |
| `TEAMS_WEBHOOK_<ID>` | A Teams workflow URL. | Not set. | Holds the URL for a [Teams alert entry](#teams-keys). |
| `LOG_FORMAT` | `json` or `text`. | `text`. A Google Cloud job uses `json`. | Sets the form of each line from `pdt.utils.log`. |

### AWS env vars

| Env var | Allowed values | Default | What it does |
| --- | --- | --- | --- |
| `AWS_PROFILE` | The name of a profile in `~/.aws`. | Not set. | Selects the sign-in when `platform.profile` is empty. |
| `AWS_REGION` | An AWS region name. | Not set. | Selects the region when `platform.region` is empty. The deploy then asks no region question. |

## `.env` files

A `.env` file holds one `NAME=value` line for each env var. `pdt init` creates one in the project folder and adds `.env` and `.env.*` to `.gitignore`. A build never includes these files.

When a name has more than one value, pdt uses the first value in this list:

1. An env var in the terminal or the CI variables.
2. The `.env` file in the app folder.
3. A `.env` file in each folder above the app folder, nearest first. pdt stops at the folder that holds `pdt.yml` or `.git`.
4. A value in `PDT_ENV_JSON`.

`pdt run`, `pdt validate`, and `pdt deploy` print each `.env` file that they read, and each name that the terminal already sets.

On a cloud provider, the job does not read your `.env` file. A deploy, or `pdt secrets APP save`, sends the values to the secret store of the cloud. On the `windows` provider, the job reads your `.env` file at each run.

### `.env.<provider>` files

`pdt secrets APP get` copies the deployed values into a file in the app folder. The default name is `.env.aws`, `.env.azure`, or `.env.google-cloud`. pdt writes this file and never reads it. To use a value from it, copy that value into `.env`.

## The `.pdt` folder

pdt creates this folder in the project and keeps it out of git. Do not edit the files in it.

| File | What it holds |
| --- | --- |
| `.pdt/state` | JSON with `deployed`, the list of deployed apps, and `platforms`, the place of each app. It also holds `alerts_offered` and `aws_preflight_passes`. |
| `.pdt/apps` | The list of app names for tab completion. |
| `.pdt/gui.sqlite3` | What `pdt gui` fetched. |
| `.pdt/storage/<app>/` | The storage folder of `pdt run` on your computer. |

A deploy writes the place of the app in `.pdt/state` before the provider script starts. A failed deploy keeps that record. Only a destroy that succeeds clears it.

`.pdt/state` changes what pdt does in these ways:

- When the config files name another place than the record, `pdt deploy` asks you to remove the app from the old place, or to cancel.
- `pdt destroy` removes the app from the place in the record, whatever the config files say now.
- When the file is missing or not valid, pdt treats every app as not deployed.

## Other files in an app folder

These files also change what pdt does with an app.

| File | What it does |
| --- | --- |
| `run.py` | The job of a Python app, or the server of a web app. Next to `requirements.psd1`, it replaces the built-in runner of a PowerShell app. |
| `run.ps1` | The only entry script of a PowerShell app. |
| `requirements.psd1` | Replaces the PowerShell modules that pdt finds in the scripts. `pdt new APP --from-scripts` writes it. |
| `Dockerfile` | Replaces the generated Dockerfile on a cloud provider. See [Bringing your own Dockerfile](platforms.md#bringing-your-own-dockerfile). A web app folder with a `Dockerfile` and a `pdt.yml` needs no `run.py`. `pdt validate` reports it on the `windows` provider. |
| `.dockerignore` | Keeps files out of the image. |
| `env.template` | Lists the names that an example app needs, for you to copy into `.env`. pdt does not read it to run the app. |
